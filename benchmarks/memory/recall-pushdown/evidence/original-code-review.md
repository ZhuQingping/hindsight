# 原型代码与证据审查

范围：本报告目录的 SQL/C/Python 原型及独立 PG worktree。按 Hindsight code-review 标准检查；本轮未派发独立专家，不宣称多人评审共识。

## 通过项

- 没有修改现有 Hindsight 业务代码、benchmark 维护代码、部署配置、原 Bank 或原 PG 工作区。PG 扩展补丁可在 f5cc81719e6 基线上 `git apply --check`。
- PGXS 编译成功。C 文件经 PG 自带 pgindent 整理；函数校验数组维度、长度、空值、负值、非法浮点常数，并包含取消检查。不存在自定义网络调用或 SECURITY DEFINER。
- RRF 以输入首次出现序号打破分数并列；先累加全部来源，再使用有界堆选 K。浮点求和顺序与 Python 保持一致。不会用尚未算完的分数错误剪枝。
- SQL 全部约束到指定 Bank；关联表通过已限定 Bank 的事实/关系访问。schema 经标识符检查，输入文本、向量、Bank 等使用参数。
- 预算函数与既有选择函数差分；完整 JSON 的最终预算仍调用已完成运行中冻结的 pack_context，不以单条长度相加替代序列化校验。
- 实验驱动校验独立 data_directory；只在克隆实例运行。向量与评分时间冻结；输出逐条核对；随机交错，保留全部尾延迟和早期失败轮次。
- 模型真实用量未知不当作零；未运行 reader/judge 就不报告新的准确率。BGE 76/81 明确归属原打榜会话。

## 投产阻断项，未冒充已经解决

1. C 函数不是 CustomScan。输入数组和候选全部生成后才融合；没有流式停止、跨臂安全上界或本次实际查询内并行。
2. 适配器要求已经解析时间条件，缺少完整扩展加载和认证/租户生命周期。仅支持显式列出的研究形状；两道时间题回退。不允许安装到 8892。
3. 新 SQL 统一了并列规则，与既有集合迭代顺序不同；候选集合一致不足以让其成为语义等价的产品替换。正式 A/B 前必须处理这个差距。
4. 未完成当前 API 的全部形状、模型故障、来源/实体、取消和并发读写的真实黑盒回归。因此本次只能交付研究原型和补丁。
5. C 状态仍持有全部唯一候选的哈希表，未提供 work_mem 溢写或资源配额产品实现；当前快照的候选至多 109 条。不能未经验证将其用于无界输入。

## 检查边界

新增文件均在研究目录与独立 PG contrib 原型目录；Hindsight 产品 Python/TS 没有改动。因此未在并行工作的现有仓库运行会自动改写业务文件的全局 lint；对新增脚本单独执行 Ruff、格式、ty、真实 PG 测试及源排名差分。本轮没有调用新增 HTTP 产品接口，产品黑盒测试属于投产阻断项而非已完成项。

结论：可接受为有边界的研究交付；不可作为可部署产品后端，也不能作为下推提高 LoCoMo 准确率或完整 HTTP P95 的证据。
