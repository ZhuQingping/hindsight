## 2. 受控实验已经证明什么

数据为旧 Bank 的 109 条事实、2212 条关系、373 条事实—实体关联、19 份文档、36 个 chunks；在独立 PG 18.4、pgvector 0.8.6 上运行，原 Bank 未写入。独立实例在早期交付结束时已停止，本次归档没有启动它。

- **原始排名回放：**C 函数对 81/81 题的 ID、顺序、RRF 分数精确一致。它证明融合计算正确，不是完整 Recall 接口验收。
- **受控响应比较：**三条路径各执行 81 题×10 轮；79 题接管、2 题回退，核对冻结响应一致。共 2430 次计时调用，不是 2430 道独立质量样本。
- **并列规则：**对未修改 store 的各臂应用同一并列规则后，79/79 题与受控 DAG 一致；原顺序并未逐题完全一致。
- **函数测试：**8 项真实 PG 测试通过，其中包含 400 轮 RRF 与 400 轮预算差分。此处不借用打榜主线的离线测试数量。

| 指标 | Python 融合对照 | C 融合路径 | 解释 |

普通 SQL 融合路径 P95 为 7.386 ms，在这个小 Bank 上还略慢。不能根据“放进 PG”就承诺稳定提速。

原型没有消除所有唯一候选的处理，哈希状态仍保存候选，未实现 work_mem 溢写、查询内并行或动态提前剪枝。现有 109 条事实低于 Top-300，本实验也不足以检验大规模剪枝收益。

## 4. 与历史打榜结果的关系

旧 Bank 的 RRF 为 70/81，本地 BGE 为 76/81；BGE 那轮 HTTP Recall P95 约 6.85 秒。它是已经完成的排序实验，**不是数据库下推成绩**。后来全量基线及 V1 使用自己的 Bank、配置和分母，以[打榜主计划](../plan.md)为准。

新 DAG 的最终上下文没有与历史旧答卷逐题完全一致，源码分支与部署也有差异，因此不能给原型直接标注 70/81 或 76/81。
