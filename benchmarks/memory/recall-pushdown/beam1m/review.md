# 本轮代码、实验与报告检视

检视对象：基线 `05d2894c5` 上的 BEAM opt-in 适配、P3 SQL、验证工具及最终证据。按仓库 code-review 与 workflow-review 的范围、隔离、类型、测试和证据要求完成复核；本轮未启动额外 Agent。

## Findings

### Critical

未发现触及原 LoCoMo 环境、改写冻结记忆表、改动原始同分结果或把秘密写入公开交付的问题。第一版保护工作区保持干净。

### Important

1. **完整平均/P50目标未达成。** 数据库路径平均基本持平，P50略增；真实模型耗时占主导。补充探针将诊断长尾关联到 Python GC，关闭 GC 的单独控制消除了原路径大部分长尾，不能将 P95 改善说成 PG 检索算子加速。原路径按类型图任务并发，P3 循环串行。报告已明确区分 PG 入口优化、数据库诊断和受控完整 Recall，没有把 B0→P3 的收益归到原始版比较。
2. **严格等价有输入和运行范围。** `recall_beam.py` 复用受限基类的 guard；仅解除查询词数限制并由 PG 重现选词。CPython 3.11、hash seed 0 的旧同分顺序适配仍是本原型条件。外部 embedding 会变，正式核对固定同一向量；正常服务已经移除该测试控制。不能宣称任意在线请求普遍逐字相同。
3. **尚非生产发布形态。** 本轮没有新增公开 API，也没有 SDK 契约变化。真实服务 HTTP 验证完成，但一般用途发布前仍需发布客户端驱动的自动黑盒 CI、多租户/异常/并发覆盖及部署迁移；不能把当前私有数据实验当作这些覆盖。
4. **全仓 lint 不是全绿。** 已执行要求脚本，基线 `api/http.py` 有 F841（历史第 5846 行，rebase 后第 5886 行），本轮未改动。目标文件 Ruff 和 ty、相关单元测试通过。该基线问题不应通过无关改动混入本补丁。

### Minor

未选中变体以明确命名保留供审计，仅 P3 被常规开启服务选中；正式产品化时应将未采用实验移出产品包。当前 SQL 是原型式过程实现，不能宣称统一物理执行算子、跨路并行或动态上界剪枝已完成。

## Open questions

补充探针已验证同进程诊断中的长尾与二代 GC 同步，并用独立的关闭 GC 控制复核。该结果不能直接代表独立服务；还需分离真实服务中的 PG、Python 分配与 GC 时间。原有图并发改成 PG 串行与 P50 退步是否存在直接因果，也需要受控实验，不能凭源码推算收益。

## Verification

- `recall_pushdown.py` 的默认 guard 和请求字段语义不变；未开启扩展仍走原流程；原始/修改后关闭响应核对通过。
- `recall_arrays.sql` 的事实、原文补全均有 Bank 条件；动态 schema 使用 `%I`；查询模板来自认证后的服务端 builder；函数使用调用者权限，没有 SECURITY DEFINER 提权。
- 融合保留原候选顺序、逐类型预算、原浮点相加顺序；不增加 UUID ties、不减少候选。
- 模型前释放 PG 连接；最终处理只使用已返回候选包，模型后不补查。真实开启服务 61 次请求（含预热）全部命中下推；预热 PG 日志核对一次候选业务调用。
- 同一冻结数据、向量、时间、候选数、模型、评分和预算；120 次真实 BGE 响应、模型输入与分数一致。
- 额外时间请求、500 个选词组合、81 题恢复库回归、33 项单元及2项时间契约测试通过。
- 覆盖索引/计划实验在物理克隆，克隆已关闭；主实验索引未改。冻结数据测试后哈希一致。
- 额外 GC 归因四组各 100 测量、图任务调度 4 次观测均响应等价，排除在正式时延样本之外；产品 GC 未修改。
- 公开报告不包含 gold、事实正文、原始向量或凭据；私有原始证据与执行脚本保留。
