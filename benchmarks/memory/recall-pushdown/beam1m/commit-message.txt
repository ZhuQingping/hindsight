feat(recall): 优化 BEAM 单次 PG 候选处理并记录等价与性能边界

问题与范围
- 首版 05d2894c5 在完整 BEAM 会话上不支持长查询选词和 experience 数据。
- 扩展只对显式允许的 Bank 生效，保留原 Recall HTTP 接口、默认关闭路径、
  原候选顺序和同分行为；本轮属于 PG 库内函数优化，不修改 PG 主干。

实现
- 新增 BEAM 兼容适配，在同一次 PG 调用内重现原生全文选词、按事实类型的
  候选预算及 world/experience 时间扩展，保持原 SQL 模板和游标顺序。
- 用 UUID/float8 类型化数组替代候选 JSONB 拼接；通过 UNNEST、分组和连接
  批量合并实体/语义/因果分数，保留原浮点相加和 legacy 集合枚举顺序。
- 补全时按需计算向量距离，复用首版 C RRF 和 Top-300，返回所需候选与原文。
- BGE、最终评分和 Token 预算仍由 ContextBase 原流程处理；模型前释放 PG
  连接，模型后不再补查候选；不增加客户端 full_recall 参数。
- 保留投影、覆盖索引、原文传输、执行计划和函数 UNION 的实验对照；
  正常开启服务只选择 P3。UNION 未产生实际并行，不宣称实现跨路并行或剪枝。

数据与验证
- 独立 PG 18.4 / pgvector 0.8.6，完整导入 BEAM 1M 首个会话的 50 文档、
  985337 输入 Token，冻结 2524 事实、1509 原文块和 62031 关系。
- GLM 5.3 retain，既有火山 embedding，本地 CPU FP32 BGE；不切换 BM25。
- 固定相同检索向量、参考时间和预算，20 题四路与 RRF 保持一致；真实 BGE
  三轮 120 个测量响应完全一致，模型输入与分数一致。固定检索向量是明确的
  实验控制：同文本的实时 embedding 存在数值波动，失败试验未混入统计。
- 500 个选词组合、2 个额外时间窗口、恢复库 109 事实/81 题候选回归通过；
  33 单元测试、2 独立 PG 时间契约测试通过；测试后七表哈希不变。

性能结论与限制
- 最小兼容下推入口平均 248.09 ms，P3 36.88 ms；这是消除下推实现自身开销，
  不能作为相对原始 ContextBase 的收益。
- 排除模型的原流程/P3 平均 52.29/51.94 ms，P50 48.19/51.64 ms：平均基本
  持平，P50 未改善。完整 Recall 约 56 秒，CPU BGE 占约 97%，无可归因于 PG
  的明显完整平均/P50 收益，不宣称准确率或 Token 提升。
- 诊断 P95 长尾与 Python 二代 GC 停顿同步；独立 GC 控制不修改产品配置。
- 原流程按事实类型并发图检索，当前 PG FOREACH/EXECUTE 串行；该问题已记录，
  恢复真实并发尚未实现，不能把一次 SQL 调用表述为并行执行。
