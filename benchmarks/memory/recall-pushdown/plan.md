| 顺序 | 工作 | 交付与通过条件 |
| --- | --- | --- |
| 1. 人工接手复测 | 按使用手册构建最终模块，在独立库复核默认 20 题、2 道时间题和评分位比较；完成当前版真实 BGE 全 20 题 | 响应、四路顺序/RRF、模型输入与原始版一致；一次候选调用，零后续查库；记录最终源码及库哈希 |
| 2. 最终构建的公平时延验证 | 固定数据、向量、时间、配置；原始 / P3 / 当前三个独立进程；每组 400 次，预热排除，外部客户端交错 | 平均、P50/P95、失败率、逐题差值和置信区间齐全；与历史 53.48→44.75 ms 分开记录，不覆盖旧结果 |
| 3. 解释退化题及剩余数据库成本 | 针对 3 道平均退化题，采集计划、buffers、内部 SQL、序列化及分段耗时 | 找到可复现原因，避免用减少候选或修改同分顺序换速度；新增优化有独立消融对照 |
| 4. 有收益再做图并发 | 对齐原应用按事实类型并发的图检索；区分依赖种子的图扩展与可独立任务；单独设计快照、worker 和顺序合并 | 真实并发，不是调一个 parallel 参数；调度开销计入，平均和 P50 有稳定净收益且严格等价，否则不采用 |
| 5. 扩大适用范围 | 更大事实/关系量、多 Bank、租户隔离、并发、不同请求和运行环境、SDK 黑盒 | 保持原基线无额外排序；完整回归、资源/取消/错误行为通过后再讨论正式启用 |
