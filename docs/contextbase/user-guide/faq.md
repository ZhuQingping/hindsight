# 常见问题

## 写入成功后，为什么没有立即查到内容？

先确认成功的是同步处理还是异步提交。异步写入需要等待任务状态变为 `completed`。

随后核对服务地址、Bank、Key 权限，以及标签和类型筛选。Recall 根据问题选择相关记忆，并非完整列出文档内容；确认来源是否存在时，可以读取文档详情。

## Retain 完成后，观察和知识页都更新了吗？

不一定。主要写入、观察整理和知识页刷新可能是不同任务。依赖某项结果时，确认对应任务或页面状态。

## Recall 返回的是完整会话吗？

通常不是。Recall 主要返回从来源内容提取或综合形成的相关记忆，不会固定先选定某个会话再检索。

需要原始上下文时，请求来源分块或读取文档详情。可用内容取决于原文保存配置和返回预算。

## 如何让多个 Agent 共享记忆？

连接同一服务，选择同一 Bank，并分别配置有相应权限的凭据。

共享的是已经写入服务的内容。某个 Agent 尚未提交的本地上下文，不会仅因使用同一 Bank 就自动共享。

## 如何隔离不同项目？

需要分别管理访问权限时，使用不同 Bank 并分别授权 Key。同一个 Bank 内可用标签筛选主题，但标签不替代服务端授权。

当前编程工具适配器配置使用一个共享的 `bankId`。`--project-path` 只选择宿主注册目录，不会按目录自动切换 Bank。

## 同一个文档 ID 再次写入会怎样？

默认 `replace`：替换旧内容并重新处理。`append` 将新内容拼接到旧正文后重新处理。

需要独立管理的来源使用不同 ID。替换时提交希望保留的完整新正文。

## 业务 Key 可以创建 Bank 或登录控制台吗？

不能。工作空间、用户和 Key 由管理员管理，业务 Key 用于已授权的业务接口。

控制台管理员登录与普通成员的业务身份是不同机制。应用取得 API 地址、业务 Key 和 Bank ID 后即可接入，无需自行登录控制台。

## 只读 Key 为什么能调用 Reflect？

Reflect 读取已有业务内容并生成回答，属于只读业务能力，但仍会调用模型，并可能产生用量和日志记录。

## MCP 已连接，为什么没有自动保存会话？

MCP 连接提供工具调用能力。自动保存还依赖宿主适配器、Hooks 或插件的启用与实际执行。

远端 MCP、CodeArts Agent 和 CodeArts CLI 的上述接入方式需要主动调用记忆工具。其他宿主也应单独验证自动保存，不以“已连接”作为成功依据。

## Python 的异步方法与异步写入有什么区别？

`aretain` 是异步 I/O 方法；`retain_async=True` 才是请求服务端后台处理。`await aretain(..., retain_async=False)` 仍等待主要处理完成。

Node.js 同样如此：`await` 等待调用返回，`async: true` 决定是否后台写入。详见[异步任务](api/operations.md#sdk-中的两个异步)。

## 如何调整 budget 和 max_tokens？

先使用默认值，再结合查询效果、处理时间和上下文长度调整。

`budget` 是处理预算，取值为 `low`、`mid`、`high`，提高预算可能增加耗时和资源使用。Recall 的 `max_tokens` 控制返回记忆的内容量；Reflect 的 `max_tokens` 控制回答内容量，两者都不是结果条数。

## 更换 Key、切换 Bank 或卸载工具会删除记忆吗？

不会。Key 控制访问权限，Bank 选择决定后续请求的位置。吊销 Key、卸载集成或切换 Bank 不等于删除服务端数据。

删除内容需要明确执行文档或工作空间删除操作。

## 请求超时，可以直接重试吗？

读取请求可以结合错误类型进行重试。写入超时意味着结果可能未知，不一定是服务端未执行。

异步 Retain 可以提前保存客户端生成的 `operation_id`，超时后查询状态，或用相同 ID 重试同一请求。不要生成新 ID 无条件重复写入。
