# 运行状态、审计与模型调用

概览用于快速了解内容与处理状态，后台操作用于跟踪任务，审计记录用于查看业务操作，模型调用明细用于理解一次处理中的模型请求。排查时先确定对象和时间，再选择相应入口。

## 读懂概览

进入工作空间的“概览”，可以查看记忆存储统计、知识页、最近文档、关系探索及记忆活动。

| 内容 | 含义与使用方式 |
| --- | --- |
| 记忆 | 当前空间的记忆节点统计，结合记忆构成理解类型 |
| 文档 | 当前空间的来源文档数量，不是提取的记忆数量 |
| 工作空间链接统计 | 存储的记忆关系链接统计，结合链接类型查看 |
| 记忆构成 | 世界事实、经历与已启用的观察等分类 |
| 知识页 | 已建立的主题目录和页面，可继续进入知识视图 |
| 最近文档 | 最近来源的入口，不是全部文档列表 |
| 处理中、待处理或失败提示 | 用于进入相应运行记录，确认具体任务 |
| 待整合记忆 | 尚待后续整理的内容，不等同于写入失败 |

关系探索是当前加载范围内的预览，页面可能展示“已显示 / 总数”。图中还可能绘制派生连线，因此图内连线数与工作空间链接统计不要求相等。

### 记忆活动图的时间口径

图表标题会说明使用哪个时间字段。按需切换：

| 时间 | 回答的问题 |
| --- | --- |
| 摄入时间 | 记录在何时进入服务 |
| 提及时间 | 事实在何时被提及 |
| 发生时间 | 底层事件在何时开始发生 |

一条今天导入的历史故障，摄入时间与事件时间可以不同。观察不同时间图或文档列表时，应先对齐时间口径和筛选范围，再比较数量。

## 设置与运行

“设置与运行”中的常用入口包括：

| 入口 | 用途 |
| --- | --- |
| 运行概览 | 记忆存储、整合、心智模型与后台操作状态 |
| 功能配置 | 提取目标、回答要求、原文保存和审计等常用设置 |
| 记忆防护 | 查看和调整实例开放的防护配置 |
| 审计日志 | 按条件查看已记录的业务操作 |

功能是否可见及可用，取决于实例开放能力。常用配置的含义见[控制台使用](console.md#8-常用设置与后台操作)；默认界面不要求用户调整所有引擎技术参数。

## 查看后台操作

在“运行概览”中找到后台操作，按类型和状态筛选。打开目标记录后，查看任务 ID、创建与更新时间、完成时间、进度、错误，以及可用的关联文档。

| 状态 | 常见处理 |
| --- | --- |
| 待处理 / 已延后 | 查看是否等待执行或后续时机，避免重复提交 |
| 处理中 | 继续跟踪进度和更新时间 |
| 已完成 | 核对本次任务对应的业务内容 |
| 失败 | 读取错误，处理原因后再使用可用的重试操作 |
| 已取消 | 确认实际停止范围及已经完成的部分 |

操作按钮按任务状态提供，不是每个任务都能随时取消或重试。取消属于停止后续处理，不代表回滚已经完成的内容；删除操作记录也不等于删除来源文档。

异步写入、文件转换、观察整理和知识刷新是不同任务。某个写入任务完成，不表示所有后续整理都完成。

## 查询审计日志

打开“设置与运行 → 审计日志”：

1. 确认当前工作空间和需要排查的时间范围。
2. 根据需要选择操作类型，例如 Retain、Recall 或 Reflect。
3. 按 HTTP、MCP 或系统等传输方式缩小范围。
4. 在列表中查看时间、操作、传输方式和耗时。
5. 点击记录，查看实际保留的请求、响应及元数据。

请求量图与日志列表都可用于判断某段时间是否出现相应操作，但比较时要确认各自的时间范围和筛选条件。

审计记录需要相应的记录能力已经开启。界面提示“未启用”时，由管理员核对当前空间的有效设置及实例能力。空列表也可能由时间、操作或传输筛选造成，不能仅据此判断业务从未调用。

审计记录反映已记录的操作，不自动充当所有后台任务的完成凭证。异步处理仍应核对任务状态。

## 查看模型请求明细

当前控制台没有独立的“LLM Requests”列表页。模型请求通过已有内容或请求的追踪入口查看；不要在“设置与运行”中寻找一个固定的同名菜单。

### 从来源文档查看写入调用

1. 打开“文档”，进入目标文档详情。
2. 当有可用记录时，找到“保留追踪”，即 Retain 写入处理的追踪。
3. 选择对应时间的一次处理，打开运行与模型调用明细。
4. 在调用序列中选择条目，查看提供方、模型、状态、时间、耗时和实际保留的输入输出。

同一文档可以经过多次写入或重新处理，应按时间和请求标识区分，避免把上一次调用当作当前结果。

### 怎样理解明细

| 信息 | 用途 |
| --- | --- |
| 操作与调用范围 | 判断本次调用属于提取、整理或其他处理阶段 |
| 提供方与模型 | 确认实际使用的模型 |
| 状态与错误 | 区分成功调用和模型请求失败 |
| 输入、输出及相关 token 字段 | 查看服务实际记录的用量；字段是否齐全取决于提供方和记录内容 |
| 调用序列、Span 与父 Span | 理解同一次运行中的调用关系 |
| 创建或使用的记忆标识 | 在有记录时，将模型调用与内容对应起来 |

未记录某个字段时，不应把空值当作零用量。审计操作耗时、模型调用耗时和后台任务总时长也不是同一个指标。

### Reflect 的运行追踪

在 Reflect 的选项中按需开启“包含工具”，执行后展开诊断详情，查看返回的工具步骤和模型调用信息。“包含来源”用于查看回答依据，两者用途不同。

Reflect 返回的本次执行追踪与文档中保存的写入追踪也不同。排查提取结果时从来源文档进入；排查一次回答怎样形成时，从该次 Reflect 结果进入。

### 没有追踪入口或记录

文档写入时未保留追踪、当前没有对应记录，或记录接口不可用时，该区域可能不显示。打开详情不会补录过去没有保存的模型输入输出。

维护程序还可以通过获得授权的审计和模型请求接口读取记录；业务 Key 的普通内容读写权限不等于管理员诊断权限。接口可用范围以实例配置和实际授权为准。
