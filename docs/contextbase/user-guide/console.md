# 控制台使用

控制台用于管理工作空间、查看来源与记忆、验证检索和维护知识页。当前服务的控制台由管理员登录；普通成员使用业务 Key 接入应用或 Agent，不会因创建了成员就获得个人控制台登录账号。

本节按“准备空间 → 添加来源 → 检查记忆 → 查询与回答 → 整理知识”的顺序介绍日常操作。页面只显示服务实例已经开放的功能；文件解析、原文保存、观察生成等能力受实例和工作空间配置影响。

## 1. 准备工作空间与业务 Key

使用服务方提供的控制台地址和管理员登录凭据进入：

1. 在工作空间目录选择“创建工作空间”，填写名称和可选描述。
2. 确认空间可用，并记下它的 Bank ID。名称用于 API 调用，会规范为小写；使用以字母开头、由字母、数字或下划线组成的 1～54 位名称。
3. 在“成员”中创建或选择业务成员，再进入该成员的“管理 API Key”。
4. 创建 Key，选择目标工作空间，并指定只读或读写权限。
5. 保存签发时展示的完整 Key，将业务 Key、Bank ID 和对外 API 地址交给应用使用。

完整 Key 只在签发成功时展示一次。Key 列表不能重新取回明文。成员用于归属和管理 Key；访问哪些空间、可以执行什么操作，配置在每把 Key 上。

本次试用需要写入资料，应使用目标空间的读写 Key。只读 Key 可以用于后续查询应用。控制台的管理员身份与应用的业务身份应分别验证，不能因控制台操作成功，就推断某把业务 Key 已有权限。

## 2. 进入正确的工作空间

从工作空间目录进入目标空间，或使用空间选择入口切换。进行导入、查询、修改或删除前，先确认当前 Bank。

常用页面：

| 页面 | 日常用途 |
| --- | --- |
| 概览 | 了解文档、记忆和知识的总体情况 |
| 文档 | 管理来源正文、标签、分块和相关记忆 |
| 记忆 | 查看世界事实、经历与观察，追溯来源或纠正事实 |
| 检索 Recall | 验证自然语言检索结果和来源 |
| 推理 Reflect | 基于当前空间的内容提问，查看回答与依据 |
| 知识 | 通过目录浏览、创建和维护知识页 |
| 设置与运行 | 查看常用配置、后台操作和已启用的审计信息 |

文档数不等于记忆数。一篇来源可以提取多条事实，后续还可能形成观察；某些详情页会包含派生内容，与只计算直接记忆的列表数字也可能不同。

## 3. 添加文本或上传文件

打开“文档”，选择“添加文档”。

### 添加文本

1. 选择“文本”，填写正文。
2. 为需要持续维护的来源填写稳定的文档 ID，例如 `alpha_project_overview`。
3. 在上下文中说明资料属于什么项目、记录什么事情。
4. 根据需要填写事件日期、标签和元数据。
5. 提交后确认处理状态，再进行首次检索。

正文可以先使用：

> Alpha 项目使用 PostgreSQL 16。数据库结构变更需要经过代码评审，并在预发布环境验证后再发布。

事件日期描述内容发生的时间。正文中的“下周”“本次”等相对表述应有足够背景，以免后续脱离会话后难以理解。

### 上传文件

在“上传文件”中选择文件，并按需要为各文件填写文档 ID、上下文和标签。使用实例支持的格式与解析方式。

上传完成不等于记忆已处理完成。文件会在后台转换、提取；可以查看对应文档的处理中状态或到后台操作页检查任务。失败时先查看错误，再决定是否重新提交。

页面没有开放上传入口或相应解析方式时，由管理员核对实例能力。不要把归档导入当作普通文件上传：归档导入接收服务导出的归档，日常 PDF、Word 或文本资料走文件上传入口。

## 4. 检查文档、分块和提取结果

在文档列表按 ID 筛选，打开一份来源。详情中可以查看：

| 位置 | 看什么 |
| --- | --- |
| 概况 | 文档 ID、时间、标签、元数据及原文 |
| 原始分块 | 实际处理的来源片段 |
| 派生记忆 | 与这份来源有关的事实、经历及后续观察 |

检查时先核对原文，再看提取的信息是否保持了对象、范围和时间。类型为“世界事实”不意味着内容已经由服务核实，只表示一种记忆类型。

如果页面提示没有保存原始文本，原文和分块可能不可用。此时仍可查看派生记忆，但不能从空原文字段推断文档没有被处理。

## 5. 修改、纠正与删除

不同问题使用不同操作：

| 情况 | 操作 | 影响 |
| --- | --- | --- |
| 来源正文变化 | 在文档详情编辑正文并保存 | 按来源重新写入，替换并重新提取相关记忆 |
| 分类或筛选标签变化 | 修改文档标签 | 替换完整标签集合，相关观察可能随后重新整理 |
| 原文正确，某条事实提取不准确 | 在事实详情进行纠正 | 修改该事实，并重新处理相应关联与派生内容 |
| 某条事实不再适用，需要保留记录 | 将事实标记失效 | 不再参与 Recall / Reflect，可在已失效内容中查看或恢复 |
| 希望按当前配置重新处理原来源 | “重新处理文档” | 提交后台任务，完成后核对新结果 |
| 整份来源不再需要 | “删除文档” | 删除来源及其提取的记忆和相关链接 |

事实的纠正、失效和恢复适用于世界事实与经历。观察属于派生内容，应从其来源事实和整理过程入手，不把它当作任意可编辑的原始记录。

如果原文也有错误，应同步修正来源。只改一条派生事实而保留错误原文，后续重新处理时可能再次提取出旧内容。

删除文档不可撤销。需要更新一份规范时，优先维护原文；不要通过反复追加冲突表述代替更新。

重新处理需要可用的来源内容。未保存原文时，应重新提供原始资料，不能仅靠提取出的事实恢复完整文档。

## 6. 验证 Recall 与 Reflect

### 检索记忆

打开“检索 Recall”，输入“Alpha 项目的数据库变更需要做哪些验证？”。

先使用默认预算，确认相关类型已勾选，再根据需要限定标签。如果需要排除没有标签的记忆，选择严格的标签匹配方式。

查看结果时，不只看相关度，还应点开记忆，确认来源文档、时间与上下文。需要原始片段时启用分块返回。没有命中时，先检查空间、任务状态和筛选条件，再调整查询与预算。

### 基于记忆回答

打开“推理 Reflect”，输入同一个问题，开启“包含来源”后执行。界面中的“推理”对应本指南所说的“基于记忆回答”。

查看回答下的依据，确认它使用了预期资料。来源不足时，应补充或修正资料，而不是只反复改写问题。Recall 和 Reflect 的筛选条件也应保持一致，便于比较结果。

## 7. 创建并维护知识页

以下示例使用专门保存 Alpha 项目资料的 Bank。

1. 打开“知识”，选择“新建文件夹”，名称填写“项目手册”。
2. 选择“新建知识页”，名称填写“数据库变更规范”。
3. 在“源查询”中填写：“整理 Alpha 项目的数据库版本、变更评审与发布验证要求，说明依据和适用范围。”
4. 选择父级文件夹“项目手册”，提交创建。
5. 等待生成，打开正文，并查看页面的更新时间、状态和记忆依据。

源查询是以后重建页面时要回答的问题，不是已经写好的页面正文。应描述需要整理的主题和范围。

### 生成范围

当前控制台的创建表单默认不添加标签，因此页面从整个 Bank 读取资料。项目独立 Bank 可以按上述流程使用。

混合保存多个主题时，应通过“心智模型选项”确认页面的范围、标签匹配和刷新配置；需要从创建时就限定范围，可以使用[知识页 API](api/documents.md#创建知识页)。

知识页标签参与选择生成资料，并非普通的装饰性分类。默认严格匹配全部标签：如果记忆只有 `project:alpha`，给页面额外设置一个未使用的 `type:handbook`，可能使它找不到任何来源。用文件夹组织目录，用实际存在于来源中的标签控制范围。

### 更新和排查

需要修改主题时，使用知识页“编辑”调整名称和源查询。更改源查询会触发内容重建。

在“心智模型选项”中，可以查看配置、历史和错误，并根据需要手动刷新。页面存在不等于生成成功；看到空正文、生成中或刷新失败时，检查任务和错误，再核对 Bank 内是否已有符合范围的记忆。

自动刷新取决于页面的实际触发配置。来源变化后，确认页面已经完成相应刷新，再把页面作为最新材料使用。

## 8. 常用设置与后台操作

默认的简化设置保留与日常使用有关的选项：

| 设置 | 用途 |
| --- | --- |
| 希望记住什么 | 引导提取时重点关注的内容，例如技术决策、适用前提和验证结果 |
| 回答要求 | 指导 Reflect 的回答目标与表达方式 |
| 存储文档原文 | 决定是否保留原始文本及分块 |
| 启用审计日志 | 按空间配置相关业务操作的记录 |
| 记忆防护 | 启用实例提供的防护能力 |

例如，项目助手的提取目标可以写为“关注已确认的规范、设计决策、理由和排障结论”；回答要求可以写为“先给结论，再说明依据和适用范围”。

这些说明用于指导处理，不代替接口权限或业务校验。修改提取设置不会自动重写全部历史来源；需要时对相关文档重新处理。开启原文保存也不会补回过去未保存的文本，需重新提供相应来源。

在“设置与运行”的后台操作中，按类型和状态查看写入、文件转换或知识刷新任务。取消任务不是回滚已完成的处理；删除操作记录也不是删除来源文档。
