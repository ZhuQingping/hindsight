# 成员与 API Key 管理

管理员在控制台中管理当前实例的成员与 API Key。成员用于标明 Key 的归属，实际访问范围和操作权限配置在每把 Key 上。

工作空间保存内容，成员和 Key 管理访问。删除或停用成员、吊销 Key，不等于删除工作空间里的记忆。

## 管理入口与身份

使用独立的管理员登录凭据进入控制台，打开“成员”。普通业务 Key 不能用于网页登录；创建成员也不会自动产生一个个人控制台账号。

首次接入可以按以下顺序准备：

1. 创建工作空间，确认 Bank ID 和服务地址。
2. 新建业务成员，用名称区分应用、团队或其他实际使用方。
3. 为成员签发 Key，明确授权空间和权限。
4. 保存签发时的明文，交付业务应用。
5. 使用业务 Key 验证写入或查询，确认授权符合预期。

工作空间的首次创建见[控制台使用](console.md#1-准备工作空间与业务-key)。

## 查看与新增成员

成员列表展示名称、状态和创建时间，支持搜索与分页。名称用于识别使用方，具体操作仍绑定到成员对象；排查同名记录时应核对其 ID。

新建成员：

1. 点击“新建成员”，填写名称并提交。
2. 确认列表中的新记录及状态。
3. 点击该成员行的“API Key”，展开其 Key 列表。
4. 根据需要继续创建 Key。成员创建本身不会自动签发 Key。

修改名称时，在该行的“更多”中选择“修改成员名称”。改名不用于转移工作空间内容，也不代替 Key 授权变更。

## 停用、启用与删除成员

| 操作 | 在哪里执行 | 对访问的影响 |
| --- | --- | --- |
| 停用成员 | 成员行的“更多 → 停用成员” | 该成员的全部 Key 无法继续通过后续认证 |
| 启用成员 | 已停用成员的“更多 → 启用成员” | 未吊销的 Key 可以恢复使用 |
| 删除成员 | 成员行的“更多 → 删除”并确认 | 该成员及其 Key 不再可用，不能按普通启用操作恢复 |

这些操作保留工作空间及其记忆数据。已经受理的请求或后台任务不会仅因成员停用而自动取消。

只需要暂时阻断某个成员的全部访问时，可以停用；只需要让一把 Key 失效时，吊销相应 Key 即可。

## 查看与签发 API Key

展开成员的“API Key”后，可以查看名称、脱敏标识和授权范围。在“密钥详情”中查看 Key ID、创建时间和最后使用记录。

列表用于识别和管理 Key，不提供已签发明文的再次读取。最后使用记录也不能替代具体业务请求或任务的成功状态。

签发新 Key：

1. 点击“创建 API Key”，填写便于识别用途的名称。
2. 选择“指定工作空间”或“全部工作空间”。
3. 指定只读或读写权限。
4. 创建成功后立即复制并保存完整 Key，再关闭展示窗口。
5. 将它配置到应用或 Agent，并按预期权限进行验证。

完整 Key 只在签发时展示一次。记录 Key ID 和脱敏标识，有助于后续找到需要编辑或吊销的对象。

## 设置授权范围

| 授权方式 | 适用情况 | 权限规则 |
| --- | --- | --- |
| 指定工作空间 | 只访问部分空间，或各空间需要不同权限 | 为每个选中的空间分别设置只读或读写 |
| 全部工作空间 | 应用需要覆盖当前实例的全部空间 | 使用统一权限，包含未来新创建的空间 |

例如，同一把 Key 可以对研发空间读写，对客服空间只读。这种差异授权使用“指定工作空间”；“全部工作空间”不提供逐空间例外。

| 权限 | 可以做什么 | 管理边界 |
| --- | --- | --- |
| 只读 | Recall、Reflect，以及允许的记忆、文档、知识读取 | 不能写入或修改业务内容 |
| 读写 | 只读能力，加 Retain 及允许的内容增改删 | 不包含空间、成员、Key、配置管理和归档导出等管理能力 |

Reflect 仍会调用模型，并可能产生用量与日志。获得全部空间的读写权限，也不等于成为管理员。

## 编辑 Key 名称与权限

1. 在成员的 Key 列表找到目标 Key，核对 Key ID 或脱敏标识。
2. 点击“编辑”，修改名称或授权。
3. 检查最终选择的全部空间及各自权限，再保存。
4. 用该 Key 对新范围进行验证。

修改授权时，提交的是本次完整的授权选择。原来授权但本次没有保留的空间，将从访问范围移除。仅修改名称时，不需要重新选择全部空间。

遇到记录已变化或空间不可用的提示，应先核对当前状态，再开始新的编辑。不要把旧页面中的授权草稿当作最新状态反复提交。

## 吊销 API Key

在目标 Key 的“更多”中选择“吊销 API Key”，核对对象后确认。吊销永久失效，不能通过启用成员恢复。

吊销阻止该 Key 的后续认证，不会删除空间内容，也不会自动取消已经受理的任务。应用要停止后台工作时，还需要按相应任务的操作规则处理。

## 更换 API Key

当前没有直接“重置原 Key”的界面操作。需要更换有效凭据时：

1. 为使用方签发新 Key，并核对授权范围。
2. 更新应用或 Agent 的配置，按需要重新加载或重启。
3. 用新 Key 验证实际请求，确认业务已经切换。
4. 吊销旧 Key，并再次核对应用没有继续使用旧配置。

编辑名称或权限不会产生新 Secret。明文丢失后，不能从列表重新取回；识别并处理旧 Key 后，重新签发所需凭据。

## 结果未知时怎样处理

签发、编辑或吊销过程中发生超时或断连时，先按界面提示核对当前记录，不立即重复创建。

如果签发可能已成功，但没有保存明文，按 Key ID、脱敏标识和创建时间识别该对象；明确找到对应 Key 后吊销，再开始新的签发。仅名称相同不足以认定是同一把 Key。
