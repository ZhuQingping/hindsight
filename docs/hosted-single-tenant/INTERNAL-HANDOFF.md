# 内部协作交付清单

2026-10-12。目的：内部资源及平台接入并行准备，本项目先完成当前环境可运行的软件。请各对口人反馈已有能力、最小接入示例、测试条件及预计可用时间；无需等待下列全部就绪才启动本地开发。

## 本项目先交付

固定 Hindsight 制品和部署配置；多 key/有效期/bank 授权及内部管理 API/CLI；部署执行器和最小管控 agent；绑定已有资源的本地实例管理 API/页面；原生功能 UI 品牌/布局/导航与身份适配；本地自动化回归、故障测试、日志/探针及客户 API/SDK/MCP 示例。

管控操作会真实作用于隔离测试实例；内部 agent 已有相应能力时接入同一执行器。参考管理服务只维护本地目标，生产由内部选定控制面负责。Key 首版落实例 PG，内部可先调用该管理 API，不要求先新建中心 key 系统。

## 最小合同字段

- 实例和操作：instance_id、machine_id、operation_id、操作类型、目标 revision、制品 digest、配置 revision、关联资源 ID。
- 执行结果：已接受/执行中/成功/失败/待核对，阶段、错误码、时间、实际版本与配置、可查询结果；心跳与业务就绪分别上报。
- 重试语义：同 operation_id 不重复执行，同 ID 不同内容冲突；超时先查状态，部分成功和失联可恢复查询。
- 资源边界：明确拥有/引用资源，释放计算与入口保留 PG/OBS 数据及绑定，数据销毁另行内部操作。

接口返回差异由本项目通过适配层与契约测试收敛。上述内容是待对齐的初始合同，不假定内部已有接口与之相同。

## 内部资源何时必须就绪

当前开发和本地验收可立即推进。第一套资源用于滚动真实联调，第二套用于跨实例隔离。公测前必须在真实资源和最终身份、网关、模型、控制通道下完成[原 V01—V19 验收](INTEGRATION-AND-ACCEPTANCE.md)；本地通过不会自动转换成云验收通过。
