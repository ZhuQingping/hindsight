# Hindsight 单租托管公测工作分解

本清单用于全组件分工和排期，责任方为建议，具体负责人、投入和完成时间待内部确定。任务状态均为待实施；组件已有能力可复用，新增开发量需要对照内部平台现状确认。

范围和数据行为以[公测方案](README.md)为准，对接与测试要求见[组件对接与上线验收](INTEGRATION-AND-ACCEPTANCE.md)。

## 工作包

| 编号 | 工作包 | 交付物与完成条件 | 建议牵头 | 主要依赖 |
| --- | --- | --- | --- | --- |
| T01 | 版本与能力基线 | 固定上游版本、依赖及发布镜像；列出 API、MCP、UI、配置和数据行为；维护自有修改清单 | Hindsight 团队 | 无 |
| T02 | 组件接口合同 | 约定实例、资源、版本、配置、操作 ID；明确接口、状态、失败和重复请求语义 | 各组件共同承担 | T01 |
| T03 | 实例管理服务 | 实例归属、资源绑定、目标与实际状态；创建、查询、启停、配置、升级、释放；操作进度和失败原因可查询 | 管理平台 | T02 |
| T04 | 调度 | 创建时选择位置和规格、分配资源；处理资源不足、重复请求及失败释放 | 调度与云平台 | T02 T05 |
| T05 | 计算与网络资源 | 申请、绑定和释放专属云机器、磁盘、VPC、子网、安全组和 IP；区分实例拥有与引用的资源 | 云平台 | T02 |
| T06 | 云 PG 接入 | 创建专属 PG；验证版本、pgvector、账户权限、网络、TLS、迁移及连接配置 | 数据库与云平台 | T01 T02 |
| T07 | OBS 接入 | 创建专属 bucket、独立 AK／SK 及 bucket 权限；验证原生 S3 兼容性、文件读写与生命周期 | 存储平台与 Hindsight | T01 T02 |
| T08 | 内部模型接入 | 提供 LLM、embedding、reranker；固定型号及向量维度；验证抽取、推理及必要的文件模型能力 | 模型平台与 Hindsight | T01 |
| T09 | 构建与制品发布 | 构建 API、UI 和授权扩展，发布内部仓库，记录版本、digest、配置及启动要求 | Hindsight 与发布平台 | T01 |
| T10 | 管控 agent | 安装注册、心跳、部署、进程、配置、监控及执行结果上报，详见 A01 至 A05 | 管控团队 | T02 T05 |
| T11 | 平台身份与实例访问 | 对接客户登录、实例归属、页面访问和实例路由；后端保管服务凭证 | 管理平台 | T02 T03 |
| T12 | 多 key 与 bank 授权 | 内部创建、查询、停用、有效期和 bank 集合授权；覆盖 REST、MCP、列表及间接资源入口 | Hindsight 与管理平台 | T01 T02 |
| T13 | 实例功能 Web UI | 修改名称、布局、风格和导航，接入平台登录，保留原生功能及接口能力 | 产品前端 | T01 T11 |
| T14 | 实例管理 Web UI | 实例创建、资源选择、状态进度、配置维护、启停、升级、释放及资源信息展示 | 平台前端 | T02 T03 |
| T15 | HTTPS 与网关 | 域名、证书、续期、实例路由、可信代理头；支持 API、MCP、流式响应和文件传输 | 网络与网关平台 | T02 T05 |
| T16 | 可观测平台对接 | 机器、进程、依赖和任务的日志、指标与告警；能定位实例、版本和操作 | 可观测与管控团队 | T02 T10 |
| T17 | 客户直接接入 | 提供专属 HTTPS 地址、内部发放的 key、API／SDK／MCP 示例，保留原生协议 | Hindsight 与客户接入团队 | T12 T15 |
| T18 | 集成与发布验收 | 真实云资源和模型下验证创建到使用、原生能力、授权、重启及维护流程 | 各团队共同承担 | 相关组件集成就绪 |

依赖表示交付条件，不要求所有开发串行执行。T02 确定后，前端可按合同并行开发；云资源、模型、OBS、PG 和 agent 可独立联调。T09 的构建流程先完成，再持续集成 T12、T13 等后续修改。

## 管控 agent 工作拆分

| 编号 | 工作 | 输出 | 完成条件 |
| --- | --- | --- | --- |
| A01 | 安装与注册 | 安装包或部署入口、agent 身份、注册心跳、版本及所属实例信息 | 重启后能恢复联络，管理端能识别对应机器与实例 |
| A02 | 部署与升级 | 获取制品、依赖检查、部署、迁移与启动结果、失败记录 | 指令可追踪，重复下发安全，失败不会误报为成功 |
| A03 | 进程管理 | API 和 Web UI 的启动、停止、重启及状态；内置 worker 运行情况 | 分别检查服务，不以容器存活代替服务和任务可用 |
| A04 | 配置管理 | 目标配置、配置版本、凭证引用、下发与生效结果 | 区分热更新与重启，能查询实际版本，凭证不进入普通日志 |
| A05 | 监控管理 | 健康、日志、指标、异常与执行记录，接入内部系统 | 能区分进程、依赖和任务异常，定位到实例及操作 |

配置至少覆盖实例 ID、worker ID、镜像 digest、配置版本、PG 及迁移连接、OBS bucket 与凭证、模型地址和型号、embedding 维度、授权扩展、API／UI 地址、端口、可信代理、文件处理及日志指标。

升级应检查接入状态、正常停机、任务排空、迁移结果、启动结果及业务检查。容器或进程管理器的停止宽限应覆盖原生停止流程。应用版本回退以数据库兼容为前提；备份恢复演练不在首期范围内。

## 交付阶段

| 阶段 | 主要工作 | 阶段出口 |
| --- | --- | --- |
| P0 版本与接口 | T01 T02，核对各平台已有能力，确定负责人 | 有可引用的能力基线、组件合同及任务分工 |
| P1 单实例运行 | T05 至 T10 T15 的必要部分 | 专属机器连接专属 PG、OBS 和内部模型，HTTPS 下可执行原生流程 |
| P2 托管集成 | T03 T04 T11 至 T17 | 客户页面和直接接入可用，资源与运行状态可追踪，授权生效 |
| P3 发布验收 | T18，补齐 T19 材料 | 必测场景通过，问题归属清楚，固定镜像与配置可交付 |
| P4 邀请公测 | T19，分批邀请并跟踪问题 | 放量至规划的 10～20 个实例，运行与支持链路可用 |

P1 的部署顺序为云资源与网络就绪 → PG 与模型配置可用 → 配置下发 → 数据库迁移 → API 就绪 → UI 就绪 → 网关接通 → 业务检查。OBS 凭证和访问必须在文件相关检查前就绪。

## 条件加入项

| 项目 | 加入条件 | 不满足时的首期方案 |
| --- | --- | --- |
| 只读或只写 key | 工程评估简单可靠，或有适用且验证过的现成实现 | 指定 bank 集合内保持原生操作能力 |
| 资源限额 | 可通过少量现成配置完成 | 给出部署规格、连接池、并发与监控默认值，延后额度产品 |
| UI 增强 | 有明确价值且不阻塞原生能力等价交付 | 先完成名称、布局、风格和平台接入 |

上游存在部分授权扩展与修复，当前未找到可直接启用的完整多 key、有效期及 bank 授权实现。只读／只写也不能按一个现成开关估算，需覆盖操作分类和间接访问。

## 待落实的工程信息

以下信息由对应工作包落实，不改变已确认范围：

- 具体负责人、协作团队、投入和排期。
- 云机器与 PG 规格、网络和可用区域、资源接口及配额。
- 镜像仓库、容器或进程管理方式、管控 agent 可复用能力。
- LLM、embedding、reranker 的实际型号、协议和凭证交付。
- 实例管理、登录、监控、日志、证书和密钥平台的实际接口。
- Key 元数据的权威存储、管理接口及生效机制，优先沿用原生扩展点。
- OBS S3 兼容性、bucket 权限、签名链接可达性与失败上传清理配置。
- 单实例实测资源使用和内部模型总并发承载。

本清单不填未经评估的人天或上线日期。排期需先核对平台复用能力；授权覆盖、UI 调整、管控 agent 和组件对接是主要工作量变量。
