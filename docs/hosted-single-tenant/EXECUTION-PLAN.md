# 单租托管执行计划：当前环境先完成可运行交付

更新：2026-10-12，依据用户最新要求。产品边界仍以 [README](README.md) 为准；本计划替代[历史探索](EXPLORATION-AND-PLAN-20261012.md)中的执行排序和“等内部合同后才开发”的建议。

## 1. 目标与推进方式

将当前环境能完成的工作做成可运行、可测试、可交接的交付物：固定制品与部署包、多 key/bank 授权、管控 agent、实例管理 API/页面、原生功能 UI 调整、监控与接入示例、自动化回归。内部团队并行准备云资源、身份、模型、控制通道及发布接入，条件到位后滚动联调。

不再将源码分析报告或接口文档作为本地阶段最终出口。源码审计是开发中的必要步骤，找到扩展落点后立即实现并补对应测试。普通本地开发、隔离测试和可逆修复按本计划连续推进，不因每个工作包重新等待计划批准；本次更新本身只修改计划，不能算功能已完成。

两条线的分工：

- **本项目直接实现**：Hindsight 应用侧适配、部署执行、最小 agent、绑定已有资源的本地管理服务/页面、授权与 UI、测试及交付包。
- **内部并行准备**：真实账号/实例归属、机器和 PG/OBS 申请、内部模型、云 HTTPS、机器身份与控制通道、镜像仓库及观测接入。可直接转发 [INTERNAL-HANDOFF](INTERNAL-HANDOFF.md)。

内部信息缺失时选择可替换、范围最小的默认实现，并记录假设与接口版本。真实云资源、组织身份和平台协议未获得验证前保留 UNKNOWN/NOT_RUN，不把测试替身算作平台交付。多租、集群、自动迁移、完整计费和备份恢复建设继续延后。

## 2. 不等待内部即可采用的默认实现

| 事项 | 当前实现选择 | 后续接入方式 |
| --- | --- | --- |
| 部署形态 | 原生 API/UI 构建目标及 API 内置 worker；先以 Docker 容器作为本地执行后端，外部 PG | 交付同一制品和版本化部署描述，接专属云 PG；内部要求其他执行后端时仅适配执行层 |
| 本地数据 | 独立测试 PG、数据库账户、S3 兼容存储及按实例隔离的 bucket/凭证 | 对应配置换成真实云资源；生产部署包不夹带本地 PG/S3 fixture |
| Key 权威 | 实例 PG 的扩展自有表，散列凭证、UTC 有效期、停用和规范 bank ID 集合；管理 API 加 CLI | 内部工具调用同一管理 API；需要接现成权限服务时通过存储/查询适配器替换，切换后只有一个权威 |
| 管控 agent | 独立于 MemoryEngine 的部署执行器与最小 agent，先连本地管理服务；安装、注册、心跳及状态可运行 | 内部机器身份、注册协议、控制通道和日志接入放在适配层；已有内部 agent 可直接承载同一执行器 |
| 实例管理 | 最小服务绑定预先提供的测试资源，持久化目标状态、操作记录，派发给 agent；用本地 SQLite 等轻量持久库 | 云资源申请/调度留给内部；生产只由选定的平台控制面维护目标，不能和本地参考服务双写 |
| 页面与身份 | 原生功能 UI 先用本地受保护会话；最小管理页面调用真实本地管理 API；身份解析和导航地址可配置 | 接入内部 SSO/归属判断。测试登录仅在本地开发模式可用，发布配置缺失真实身份时拒绝开放 |
| 模型 | 现有测试 stub 支撑确定性回归；现有获准模型配置支撑有界真实功能抽样，独立测试数据 | 内部三类 endpoint/型号到位后跑相同场景；明确区分 stub、现有模型和目标内部模型结果 |
| HTTPS | 在隔离容器和独立端口验证代理、TLS、Cookie、MCP、stream 和上传；测试客户端显式信任测试 CA | 不改变宿主机路由、全局证书信任或现有服务；最终换成内部网关、域名和证书再验收 |

内部接口初稿由本项目先提供最小示例、错误和版本语义，不等各方共同设计完成后才编码。暂定合同集中在一处管理，收到内部反馈后同步更新实现和契约测试。

## 3. 工作顺序与具体交付物

初始 E 项均为 **PLANNED / NOT_RUN**；实时状态以 [development-state.json](development-state.json) 为准。这表示尚未实现，不表示再次等待用户对每项授权。用户现已要求采用 agent 并发、状态接续和独立 review；E0—E6 进一步拆为 [D00—D14 开发工作包](DEVELOPMENT-PLAN.md)，按 [AGENT-WORKFLOW](AGENT-WORKFLOW.md) 执行。

| 批次 | 工作包 / 对应 T | 具体实现及交付 | 验收出口 |
| --- | --- | --- | --- |
| E0 首先 | 隔离工作区与环境；T01/T09 | 因体验 API 以 editable 方式使用当前源码，开发使用独立 checkout/worktree；构建脚本、固定依赖、测试专属端口/数据/凭证、制品清单 | 正式源码构建的 API/UI 能在隔离环境运行；可重复启动与清理；不改现有体验实例与其他项目 |
| E1 紧接 | 原生部署闭环；T06—T09/T15 | 外部 PG、原生 S3 后端、模型配置、代理、健康及业务 smoke；复用现有 system tests | 从部署到 retain/recall/reflect、异步任务、文件/下载、SDK/MCP 有运行证据；模型和存储测试替身明确标注 |
| E2 第一批功能 | 授权扩展与内部工具；T12/T17 | 单租 tenant extension、operation validator、key 表与迁移、管理 API/CLI、创建/查询/停用/到期/scope 更新、UI 服务身份 | REST/MCP 和间接资源允许/拒绝测试通过；无明文 key 查询；停用后新请求拒绝，已受理任务继续原生执行 |
| E3 第一批功能 | 管控 agent；T10/A01—A05 | 部署执行器、最小常驻 agent、本地注册/心跳/领取指令/结果上报、持久操作日志、配置及 secret 引用、启停升级、健康/任务观测 | 对真实隔离 API/UI 执行操作；agent 和管理服务重启、重复指令、失联、部分失败有明确结果；不是只返回模拟成功 |
| E4 跟随 E3 合同 | 实例管理 API 和页面；T03/T14 | 绑定已有资源的实例记录、目标/实际版本、状态、操作进度、启停/配置/升级/释放入口、PG/OBS 等信息、跳转功能页 | 页面操作真实派发 agent，状态可持久查询；释放保留测试 PG/对象及绑定；云资源申请显示未接入，不能伪造云创建成功 |
| E5 跟随 E2 | 原生功能 UI 与接入；T11/T13/T17 | 名称/logo/导航可配置，调整布局与风格，实例入口与本地会话适配，API/SDK/MCP 使用说明 | 浏览器实测主要原生功能、登录/退出、授权、流式与文件；浏览器不获得全权限 dataplane key；未知品牌资产采用可替换占位配置 |
| E6 集成交付 | 异常、回归与交接；T16/T18/T19 | 生命周期故障注入、双实例逻辑隔离、日志指标、诊断包、自动回归脚本、发布清单、操作手册及未完成项 | 同一制品和配置从部署到使用、维护、释放可复现；所有本地失败可定位；剩余事项精确列到真实资源/平台接口 |

优先交出 E0/E1 的可运行底座，然后尽早形成 **管理 API → agent → 真实 Hindsight → 状态回报** 的一条完整路径，再扩充操作与页面。E2 授权可在 E1 就绪后推进，E4/E5 不等真实 SSO 或云资源申请接口。内部测试资源任何阶段到位，都立即运行相关真实联调案例，不等 E6。

首版目录建议：应用扩展放 `hindsight-extensions/`；部署、agent、参考管理服务与管理页集中到独立 `deploy/hosted-single-tenant/`，避免侵入 MemoryEngine；原生 UI 修改留在 `hindsight-control-plane/`。具体结构随实现按仓库约定收敛，不为每个模块另造框架。运行状态、大日志和浏览器产物统一归集主仓库 `.local/hosted-single-tenant/`，不散落到兄弟 worktree；正式脚本、测试、合同和小型结果清单入 Git。

## 4. 管控 agent 必须做到的深度

该工作从“提供建议和合同”提升为本项目直接实现。可运行 agent 的范围限定于单台机器上的本实例应用；复用 Docker/原生启动脚本，不做通用远程 shell、自动调度或集群控制系统。

| 能力 | 当前环境的真实实现 | 必测失败场景 |
| --- | --- | --- |
| 安装、注册与心跳 | 可安装/启动的包或容器；持久 agent/instance ID；独立本地管理凭证；版本及实际状态上报 | 身份不符拒绝，心跳超时为失联；重启身份不漂移；正式身份适配未就绪不宣称平台注册成功 |
| 指令受理 | 固定操作集合：deploy/start/stop/restart/apply_config/upgrade/release/status；携带 operation_id、instance_id、目标 revision/digest | 同 ID 同内容返回原操作；同 ID 不同内容冲突；旧 revision 不覆盖新目标；单实例互斥避免升级与停止竞争 |
| 部署与配置 | 校验版本化部署描述、解析 secret 引用、准备制品、执行迁移、启动 API/UI、读真实探针；配置原子写入 | 镜像不可用、配置错误、PG 不通、迁移失败、UI 未就绪均不能标记成功；凭证不进普通日志或状态接口 |
| 进程与任务 | 独立观测 API/UI；固定 worker ID；正常停止与原生恢复；保留原生任务语义 | worker 任务未完成时停机/异常退出，重启后达到正确终态；模型/PG 故障不能只靠容器重启假报恢复 |
| 持久结果与恢复 | 指令、执行阶段和结果持久化；进程退出后检查实际容器/版本/迁移状态再继续或终止 | “已执行、未回报”窗口不盲目重做；管理端重启不丢操作；不确定状态明确标记待核对，不承诺任意外部操作 exactly-once |
| 控制面失联 | 运行中 Hindsight 保持本机既有配置；心跳/结果有界重试与持久待发送记录 | 失联不误释放实例；恢复后上报真实结果；版本冲突通过目标 revision 和查询解决 |
| 升级与回退 | 排空/停止、单一迁移执行者、启动与业务检查；记录原/目标 digest 和配置 | 数据库已升级但应用失败时报告部分成功；只执行已证明数据库兼容的应用回退，不自动反向迁移 |
| 释放与观测 | 停止应用、撤销本地访问入口，保留 PG/OBS 数据及绑定；采集健康、进程/磁盘、操作和任务摘要 | 释放重试安全、不碰其他项目容器或资源；数据销毁不混入 release；日志脱敏，操作 ID 可贯通 |

本地参考管理服务与 agent 只控制显式登记的测试资源，默认绑定 loopback 或隔离容器网络。Docker 权限限定在运行 agent 的测试环境及操作范围；不用匿名公网管理接口。接入内部现成 agent 后共用执行逻辑，选定一个控制面，移除参考服务的生产控制权。

## 5. 授权、UI 和回归同步做完整

Key 管理默认使用实例 PG，不等待中心服务。内部管理接口独立认证，普通 Agent key 不能创建或提升自身权限；UI 使用独立服务端身份。授权变更先不引入跨请求正向缓存，变更提交后的下一新请求按新状态判断；内部任务依据可信内部上下文沿用已受理语义。

逐入口审计与实现结合，至少覆盖：列表/分页、别名、懒创建 bank、retain/recall/reflect、操作查询/控制、chunk、附件/签名 URL、导入导出/clone 的源目标、MCP session 后续请求、配置/知识页/webhook/诊断。原生 hook 有缺口时用复现和最小核心补点解决，不为了坚持零修改而留下缺口。已签出的下载链接仍按自身到期时间失效。

原生功能回归覆盖事实、观察、mental model、知识页的不同终态；默认关闭后台工作的平台 fixture 需要显式开启相关场景。UI 功能等价与视觉调整同批验证，尽早产出可看的本地页面；管理页必须操作真实 agent，仅未接入的内部能力允许使用明显标识的测试替身。

遵守仓库实现规范：编码前读取适用规范，新增用户可见能力补黑盒故事；Python/TypeScript 改动运行要求的 lint 与相应测试；接口变化按要求同步 OpenAPI/客户端；实现完成执行规定的代码审查。仅在存在有意义行为变化时增加测试，避免把配置文本复制成测试断言。

## 6. 本地能完成与真实环境仍需完成的验收

| 层级 | 可以得出的结论 | 不能代替什么 |
| --- | --- | --- |
| LOCAL 实际运行 | 制品、授权、agent、管理 API/页面、原生 UI、进程/任务恢复在当前隔离环境通过 | 云 OS/规格、云网络、云 PG 权限、真实 OBS 兼容性 |
| CONTRACT_FIXTURE | 身份/资源/控制通道适配按本地约定处理成功、拒绝、超时、重试 | 内部接口已兼容、真实租户/实例归属已安全对接 |
| EXISTING_MODEL / STUB | 现有模型的有界样例或确定性协议流程已通过 | 目标内部 LLM/embedding/reranker 的质量、协议和并发 |
| CLOUD | 在真实资源、真实身份与网关、最终模型及 agent 通道下验收 | 未执行的备份恢复、集群高可用和容量承诺 |

V01—V19 沿用原编号，每个 case 附 environment_kind、版本/digest、配置 revision、预期/实际、证据位置和剩余条件。本计划更新时所有新增案例仍为 NOT_RUN；先前本地健康观察只保留为历史记录。

本地发布候选出口：E0—E6 中可本地实现的能力全部有真实运行/浏览器/异常测试证据；模拟部分逐项标识；可从干净测试资源重复部署；内部接入仅剩明确列出的适配、配置及真实验证。两实例隔离测试使用各自 PG/凭证/bucket；受开发机容量限制时分批运行，但需要并发或交叉访问的场景不得因分批而省略。容量与成本基线在目标云规格下完成。

对外公测出口不降低：真实 V01—V18 通过、至少两套专属资源隔离通过、支持和发布材料就绪后分批邀请。未接入云创建/身份/控制通道等功能不能通过本地演示宣布公测可用。

## 7. 最先执行的工作与持续交付

1. E0：建立独立开发 checkout 与隔离运行目录，读实现规范，核对可复用依赖；固定第一次构建和启动结果。
2. E1：先完成外部测试 PG、原生 API/UI、启动/停止及健康探针的最小底座，立即支撑 agent 部署闭环；S3、模型、MCP、文件和后台派生完整回归另行滚动补齐，不作为最小 agent 开发的整段前置条件。
3. E3 最小路径：本地管理服务提交 deploy，agent 真正执行，管理端展示操作及实际状态；再补启停、配置、升级、释放与恢复。
4. E2/E4/E5：在底座就绪后推进授权、管理页和功能 UI，逐项加入真实黑盒/浏览器场景。
5. E6：汇总可复现交付及待内部联调事项；内部条件提前到位时随时插入对应真实验证。

后续进度以“已可运行什么、证据是什么、还差哪个内部条件”为单位报告，不再反复产出分析方案。内部协作清单可立即同步；不自动联系其他人，不自行申请付费云资源，也不因内部未回复而停止无依赖的本地工作。
